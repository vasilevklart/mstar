Every speech recognition key serves `POST /v1/audio/transcriptions`. `qwen3_asr` and `qwen3_asr_realtime` also stream live transcripts over `/v1/realtime?intent=transcription`.

## Models {#models}

| Key | Languages | Timestamps | Realtime | Clip per request | Guide |
|---|---|---|---|---|---|
| `whisper_large_v3_turbo` | Detected, or set with `language` | word, segment | no | 30 s | [Whisper and Qwen3-ASR](/models/whisper-qwen-asr) |
| `whisper_large` | Detected, or set with `language` | word, segment | no | 30 s | [Whisper and Qwen3-ASR](/models/whisper-qwen-asr) |
| `qwen3_asr` | 30, detected or set with `language` | no | yes | 20 min | [Whisper and Qwen3-ASR](/models/whisper-qwen-asr) |
| `qwen3_asr_realtime` | 30, detected or set with `language` | no | yes | 20 min | [Whisper and Qwen3-ASR](/models/whisper-qwen-asr) |
| `canary` | 25 European; translation to or from English | no | no | 40 s | [FastConformer ASR](/models/fastconformer-asr) |

| `omnilingual_asr_ctc_300m` | 1,600+, no language code | no | no | 40 s | [Omnilingual ASR](/models/omnilingual-asr) |

| `higgs_audio` | `language` is not read | no | no | 30 s | [Higgs Audio](/models/higgs-audio) |

The transcription route accepts uploads of up to 30 minutes and 512 MiB. It cuts an upload longer than one window into windows, each ending at a quiet moment, and transcribes them in parallel. A window is the model's clip limit, with two exceptions: Qwen3-ASR cuts 30 s windows although one request can hold 20 minutes, and Omnilingual ASR transcribes clips of up to 20 s whole and cuts longer ones into windows of at most 16 s. `window_seconds` in the request, from 5 s up to the clip limit, sets the window for that request.

Only Whisper writes timestamps. For the other models, a timed `response_format` (`verbose_json`, `srt`, `vtt`) gets one segment per window, and the FastConformer models answer `timestamp_granularities` with a 400.

## Transcribe a file {#transcribe-a-file}

Install M\* from source with the Rust build ([Installation](/installation#install-from-source)) and the `asr` extra. Omnilingual ASR needs no extra.

```bash
uv pip install --torch-backend=auto -e ".[asr]"
```

Start Whisper large-v3-turbo:

```bash
mstar serve whisper_large_v3_turbo
```

The server compiles and captures its graphs before it answers. In another terminal, wait until `/health` returns 200:

```bash
until curl --fail --silent http://localhost:8000/health; do sleep 5; done
```

Upload a file and ask for word timestamps:

```bash
curl --fail http://localhost:8000/v1/audio/transcriptions \
  -F model=whisper_large_v3_turbo \
  -F file=@speech.wav \
  -F response_format=verbose_json \
  -F 'timestamp_granularities[]=word'
```

The response's `text` is the transcript, and `words` holds each word's `start` and `end` in seconds. WAV, FLAC, OGG and MP3 uploads decode with `soundfile`; other containers such as M4A and WebM go through `torchcodec`, which needs FFmpeg's shared libraries.

The same request from the Python SDK:

```python
from mstar import MStarClient

client = MStarClient("http://localhost:8000")
print(client.transcribe("speech.wav", language="en"))
```

`client.transcribe()` sends one `/generate` request, which the server does not cut into windows. Whisper hears only the first 30 s, and Qwen3-ASR, the FastConformer models and Omnilingual ASR refuse a clip longer than their limit. Send long files to `/v1/audio/transcriptions`.

To serve another model, stop the server and run `mstar serve` with that key. The request fields each model reads are on its guide page.

## Realtime transcription {#realtime}

`/v1/realtime?intent=transcription` is served by `qwen3_asr` and `qwen3_asr_realtime`. Other keys close the socket with code 1008. Start the 0.6B checkpoint, which is sized for short realtime steps:

```bash
mstar serve qwen3_asr_realtime
```

This client streams a 16 kHz mono PCM16 WAV file and prints the partial and final transcripts. `websockets` is installed with M\*.

```python
import asyncio
import base64
import json
import wave

import websockets

URL = "ws://localhost:8000/v1/realtime?intent=transcription"


async def send_audio(ws, pcm: bytes) -> None:
    for i in range(0, len(pcm), 3200):  # 100 ms of 16 kHz PCM16 per append
        audio = base64.b64encode(pcm[i:i + 3200]).decode()
        await ws.send(json.dumps({"type": "input_audio_buffer.append", "audio": audio}))
    await ws.send(json.dumps({"type": "input_audio_buffer.commit"}))


async def main(path: str = "speech.wav") -> None:
    with wave.open(path, "rb") as f:
        pcm = f.readframes(f.getnframes())
    async with websockets.connect(URL) as ws:
        await ws.recv()  # transcription_session.created
        sender = asyncio.create_task(send_audio(ws, pcm))
        async for message in ws:
            event = json.loads(message)
            if event["type"] == "mstar.transcription.partial":
                print("partial:", event["text"])
            elif event["type"] == "conversation.item.input_audio_transcription.completed":
                print("final:", event["transcript"])
                break
            elif event["type"] == "error":
                raise RuntimeError(event)
        await sender


asyncio.run(main())
```

Every `chunk_seconds` of new audio, the server transcribes everything heard so far as one engine request, with the previous hypothesis minus its last `unfixed_tokens` tokens as the start of the answer. Only that tail can change.

| Server event | Carries |
|---|---|
| `conversation.item.input_audio_transcription.delta` | New text before the unstable tail. Deltas are append-only: a later revision of text already sent is not resent. |
| `mstar.transcription.partial` | The whole current hypothesis, unstable tail included, with `audio_seconds`, the audio it covers. |
| `conversation.item.input_audio_transcription.completed` | The final transcript after `input_audio_buffer.commit`. Use it rather than the joined deltas. |

To change the session, send `transcription_session.update` with these fields under `session`:

| Field | Default | Effect |
|---|---|---|
| `input_audio_format` | `"pcm16"` (16 kHz) | Also `"g711_ulaw"`, `"g711_alaw"`, or `{"type": "audio/pcm", "rate": N}` for N in 8000, 11025, 16000, 22050, 24000, 32000, 44100, 48000. Audio is resampled to 16 kHz. |
| `turn_detection` | `null` | The client ends each utterance with `input_audio_buffer.commit`. `{"type": "server_vad"}` lets the server end it and needs the `vad` extra. |
| `input_audio_transcription.language` | unset | Forces the language. |
| `mstar.chunk_seconds` | 2.0 | Audio between steps. Values below 0.5 are raised to 0.5. |
| `mstar.unfixed_chunks` | 2 | Chunks heard before the hypothesis is fed back. |
| `mstar.unfixed_tokens` | 5 | Tokens at the end of the hypothesis that the next step may rewrite. |

An utterance holds at most 300 s of audio. Without turn detection, an append past that is an `error` event, and the client commits or clears the buffer; with `server_vad` the server commits there.

## Tuning {#tuning}

`configs/whisper_large_v3_turbo.yaml` and `configs/qwen3_asr.yaml` set `knobs: step_threads: serial`. The worker then runs a step's host work on its main thread instead of its GPU and plan threads. ASR steps have little CPU work to overlap, and on a host with the `schedutil` CPU governor one busy thread holds a higher clock than work split across threads. Add the same block to another ASR config to try it, or set `MSTAR_STEP_THREADS=serial` for one run; the variable wins over the config.

```yaml
knobs:
  step_threads: serial
```

Whisper, Qwen3-ASR and Higgs Audio cap the API server's torch threads at 4, and the FastConformer models at 1: that process only decodes uploads and stages tensors. `preprocess_torch_threads:` in the config sets the count, and `null` keeps torch's default.

## Benchmarks and parity {#benchmarks-and-parity}

The benchmarks run from the root of a checkout and need the `asr` and `eval` extras. `benchmark.asr_data` downloads LibriSpeech test-clean from openslr.org and writes the first 200 utterances and one 10-minute long-form file under `--out`:

```bash
uv pip install --torch-backend=auto -e ".[asr,eval]"
python -m benchmark.asr_data --out data/asr
```

`benchmark.asr_bench` sends that set to `/v1/audio/transcriptions` at each concurrency and reports RTFx, p50 and p95 latency and WER:

```bash
python -m benchmark.asr_bench --url http://localhost:8000 --model whisper_large_v3_turbo \
    --system "M*" --concurrency 1 8 32 --long-form --output-json results.json
```

`benchmark.asr_realtime_bench` plays the utterances into `/v1/realtime` at real time and measures partial-result latency. Run it against `mstar serve qwen3_asr_realtime`:

```bash
python -m benchmark.asr_realtime_bench --url ws://localhost:8000 --model qwen3_asr_realtime \
    --system "M*" --sessions 1 8 --output-json realtime.json
```

`benchmark/asr_reference.py` writes the Hugging Face or Qwen3-ASR SDK transcripts that WER parity is checked against. The GPU tests under `test/asr` compare both encoders with their Hugging Face modules, Whisper's greedy transcripts and word timestamps with Hugging Face, and Qwen3-ASR's greedy transcripts with the reference SDK.
