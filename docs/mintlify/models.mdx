`mstar serve <key>` starts a key with its default config. `--config` serves another layout of the same model; each family page lists the shipped ones:

```bash
mstar serve qwen3_omni --config configs/qwen3omni_2gpu_h100.yaml --gpus 0,1
```

## Matrix {#matrix}

GPUs counts the devices the default config uses. Extra is the install extra, as in `uv pip install --torch-backend=auto -e ".[bagel]"`; `all` marks a model with no extra of its own. `omnivoice`, the four Qwen3-TTS keys and `waypoint` also need a package no extra can carry ([Manual installs](/installation#manual-installs)). In the speech generation table, audio input is a reference clip for voice cloning, except on `nemotron_duplex`, where it is the user's speech.

[Verified on H200](#verified-on-h200) lists the keys that served a real request on 2026-11-27.

Every key serves `POST /generate` and `/generate/ws` ([Clients](/clients#native-generate)). Endpoints lists the OpenAI routes on top:

- chat: `POST /v1/chat/completions`
- speech: `POST /v1/audio/speech`; voices: `GET /v1/audio/voices`
- transcriptions: `POST /v1/audio/transcriptions`
- images: `POST /v1/images/generations`; edits: `POST /v1/images/edits`
- videos: `POST /v1/videos/generations`
- realtime: the `/v1/realtime` WebSocket

## No OpenAI adapter {#no-openai-adapter}

These keys have no OpenAI adapter, so their `/v1/*` generation routes answer 404. Use `/generate` or the [Python SDK](/clients#python-sdk).

- `command_a_plus`, `minicpm_o`, `waypoint`, `lingbot_world_1_3b`, `vjepa2`, `vjepa2_ac`.
- `nemotron_duplex` also serves `/v1/realtime` conversations.
- `pi05` with `configs/pi05_droid.yaml` also serves openpi's policy WebSocket ([Clients](/clients#openpi-websocket)).

## GPU memory {#gpu-memory}

Where a config's comments size it for a GPU:

- `muse_glimmer`: one 141 GB GPU, or `configs/muse_glimmer_tp2.yaml` on two 80 GB GPUs.
- `qwen3_omni`: on 80 GB GPUs such as the H100, serve `configs/qwen3omni_2gpu_h100.yaml`.
- `ripple_65b`: four 80 GB GPUs, or `configs/ripple_65b_tp2.yaml` on two 141 GB GPUs.
- `glm52`: eight 141 GB GPUs. `glm5_next`: eight 80 GB GPUs.
- `minimax_h3`: GPU 0 needs 141 GB.
- `command_a_plus`: the KV pool is sized for GB200; on 141 GB GPUs set `resources.kv_cache.max_num_pages` to 2048.

See [Supported hardware](/hardware) and [Per-request LoRA adapters](/models/lora).
