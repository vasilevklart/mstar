A model declares what each node keeps between steps in `declare_state()` and reaches it through handles. `mstar.engine.state` is the engine surface a ported package imports: `test/modular/test_state_lint.py` refuses any other engine import outside its listed exceptions ([Lint rules](/adding_models#lint-rules)). Its `__all__` only grows. [Step 2a](/adding_models#step-2a-declare-your-state), [Step 4a](/adding_models#step-4a-declare-the-step) and [Reaching your state](/adding_models#reaching-your-state) explain each name in context.

## Example {#example}

One autoregressive node with a paged KV array and a sampler. Each piece is from a file in the tree, shortened.

Declare the state on the model (`mstar/model/orpheus/orpheus_model.py`; its `Rope` also carries the Llama 3.1 factors):

```python
from mstar.engine.state import Array, Attend, Causal, KVEntry, Positions, Read, Rope, Sampler

KV_CACHE, SAMPLER, ATTN = "kv_cache", "sampler", "attn"   # the names mstar/model/orpheus/config.py defines

def declare_state(self) -> list[Array | Sampler]:
    c = self.config
    return [
        Array(
            KV_CACHE, nodes={"LLM"}, layers=frozenset(range(c.num_hidden_layers)),
            entry=KVEntry(heads=c.num_key_value_heads, head_dim=c.head_dim),
            max_len=c.max_position_embeddings,
            positions=Positions(rope=Rope(theta=c.rope_theta)),
            reads={ATTN: Read(mask=Causal(), op=Attend(q_heads=c.num_attention_heads))},
        ),
        Sampler(SAMPLER, nodes={"LLM"}, vocab_size=c.vocab_size, penalty=True),
    ]
```

Bind the handles. The node takes both (`DeclaredTokenDecoder.bind_state` in `mstar/model/components/sampled_token_decoder.py`), and each attention layer takes the array's (`ParallelAttention.bind_state` in `mstar/model/components/distributed/attention.py`):

```python
# the node
def bind_state(self, handles):
    self.kv = handles[self.KV_CACHE]
    self.sampler = handles[self.SAMPLER]

# each attention layer, built with its layer id
def bind_state(self, handles):
    self.state = handles.get(self._kv_key)
```

Call them in the forward. The layer rotates and attends; the node picks each row's last token and draws:

```python
q, k = rope(self.state, q, k)                          # rotate at this step's positions
out = add_read(self.state, self.layer, q, k=k, v=v)    # add this step's k and v, then attend

hidden = at_last_token(self.kv, hidden)                # each row's last token in this step
tokens = sample(self.sampler, logits)                  # one draw per row
```

Declare the step. `SampledTokenDecoder.declare_step` builds one `Segment(request_id, "main", span)` per row, padding rows included, and `DeclaredTokenDecoder.node_step` says what the step does to each declaration:

```python
def node_step(self, segments, prefill_tokens, advance):
    return SubmoduleStep(
        segments=segments,
        state={self.KV_CACHE: ArrayStep(advance=advance), self.SAMPLER: SampleStep(prompt_tokens=prefill_tokens)},
    )
```

Tune it in the deployment, under the declared names (`configs/orpheus.yaml` with a `resources:` block added; the values are examples):

```yaml
model: "orpheus"
max_seq_len: 131072
resources:
  kv_cache:            # the Array: a paged KV pool
    max_num_pages: 1024
    cpu_offload_pages: 128
  attn:                # its read: an attention over the pool
    flashinfer_backend: fa2
  sampler:             # the Sampler
    enable_logprobs: true
node_groups:
  - node_names: [LLM]
    ranks: [0]
    graph_walks: [prefill, decode]
  - node_names: [snac_decoder]
    ranks: [1]
    graph_walks: [snac_chunk]
```

Test it on CPU, with the Rust extension built (`maturin develop --release -m rust/Cargo.toml`, [Testing](/adding_models#testing)):

```bash
CUDA_VISIBLE_DEVICES="" HF_HUB_OFFLINE=1 python -m pytest -q \
    test/modular/test_state_lint.py test/modular/test_model_contracts.py test/modular/test_orpheus_model.py
```

## Names {#names}

Everything in `mstar.engine.state.__all__` (`mstar/engine/state/__init__.py`), by kind.

| Kind | Name | What it is |
|----|----|----|
| Declaration | `Array(name, *, nodes, layers, entry, max_len, reads=, updates=, rewritable=, labels=, positions=)` | Per request, label and layer, entries at log positions `0` to `n - 1`. `max_len=0` keeps nothing between steps; `None` has no bound. |
| Declaration | `Value(name, *, nodes, layers, entry, updates=)` | A rewritable array of one entry: a recurrent state, a carried tensor, host fields. |
| Declaration | `Entry(tensors, *, host=)` | What one entry holds: named `TensorType` fields, and host fields. |
| Declaration | `TensorType(shape, *, dtype, shard=None)` | A field's global shape, its dtype (`None` is the compute dtype) and the axis split across TP ranks. |
| Declaration | `KVEntry(*, heads, head_dim)` | An `Entry` of `k` and `v`, sharded on their heads. |
| Declaration | `Positions(rope=None)` | A position counter per request and label on an append-only array. |
| Declaration | `Rope(theta=, rotary_dim=, interleave=, scale=, low_freq_factor=, high_freq_factor=, old_context_len=, dtype=, table_dtype=, longrope=)` | The rotation the positions apply. |
| Declaration | `LongRoPE` | A short and a long factor set, picked per request by prompt length; `LongRoPE.from_hf(config)`. |
| Declaration | `Sampler(name, *, nodes, vocab_size, penalty=True, min_p=False, eos_ids=(), draws=1)` | A sampler and the kernel variants its captures record. |
| Declaration | `SeqShard(name, *, nodes, labels=, walks=None, exchange="auto")` | The node's steps may split over its SP ranks. |
| Read | `Read(mask, op=None, layers=None, walks=None, queries=None, packed=True, segmented=False)` | How a layer reads an array, per layer and walk. |
| Mask | `Causal()`, `Window(size)`, `Block()`, `Bidirectional()` | Which entries each query sees: up to its own, the last `size`, its own segment (`max_len=0`), every entry of its row. |
| Op | `Attend(q_heads)` | Attention with the model's query heads, a multiple of the entry's heads. |
| Op | `CausalConv(activation="silu")`, `GatedDeltaNet(qk_l2norm=True, scale=None)`, `Mamba2(time_step_limit=)` | Kernels that read and write a `Value`'s `conv`, `state` or `ssm` field in place. |
| Read result | `Reached` | What a read with no op returns: `fields` and `row_offsets`, tensors the caller owns. |
| Request | `SampleSettings` | One request's settings for one sampler, from `get_request_resource_configs`. |
| Request | `Layout(spans=, growth=, scratch=, max_growth=)` | What a request writes to one label, from `process_prompt`'s `state_layout`. |
| Request | `Span` | One write in a layout: `kind` (`ids`, `digest`, `rows`), `walk`, `length`, `advance`, `source`, `scratch`, `opens_step`. |
| Step | `Segment(request_id, label, span)` | One request's contribution to one label in a step. |
| Step | `ArrayStep(segments=, keep=, forks=, placeholders=, eager_add=, fixed_layout=, advance=, position_ids=, host=)` | What one step does to one array. |
| Step | `SampleStep(apply_penalty=, apply_filters=, prompt_tokens=, kept_rows=)` | What one step does with one sampler. |
| Step | `Fork(src, dst, at, rows=None)` | Fork one label from another, at `"start"` or `"end"` of the step. |
| Step | `SlotLease` | The graph slot a step replays on, passed to `declare_step` as `slot_lease`. |
| Call | `add_read(h, layer, q, *, keep=None, **fields)` | A layer's add, then its read, behind one graph break. |
| Call | `rope(h, q, k)` | `q` and `k` rotated at this step's positions with the declared `Rope`. |
| Call | `position(h, rid_handle, label)`, `positions(h)` | A request's next position on the host; this step's position ids on the device. |
| Call | `at_last_token(h, x, *, label=None)` | `x` at each (row, label)'s last token in this step. |
| Call | `sample(s, logits)`, `last_sampled(s)` | One fresh draw per row; each row's last sampled token, for a `DeviceLoopback`. |
| Call | `causal_conv(h, ...)`, `gated_delta_net(h, ...)`, `mamba2(h, ...)` | Run a `Value`'s update kernel for one layer. |
| Call | `host(h, request, label, layer)` | One entry's host fields, as the last committed step left them. |
| Call | `scatter(shard, *xs, dim=None)`, `gather(shard, *xs, dim=None)`, `split_range(shard)` | This rank's share where the step splits; every rank's share back; this rank's range. |
| State op | `state_op(*, adds=, writes=, reads=, mutates=, formats, reference)` | Make a kernel that writes state in one launch a state op, with a reference over the calls above. |
| State op | `PagedNHD(dtypes=, devices=)`, `PagedNHDTarget` | A storage format a state op can address, and where it writes this step's entries on one layer. |

A handle also has methods: `add(layer, *, keep=None, **fields)`, `read(layer, q=None)`, and on a `Value` `write(layer, **fields)` and `set_start(fields)`. A shard handle has `ranks`.

These import from `mstar.engine.state` but stay out of `__all__`, so they can change: `SubmoduleStep` (the engine's own dataclass), `kernel_setting` (temporary, with `kernel_settings()`), `MAX_POSITION_KWARG` (the prompt length a `LongRoPE` request picks its table by), and the fused draw (`fused_draw_args`, `drew`, `FusedDrawArgs`, `draw_row`, `draw_row_layout`), which one model uses.

## What the engine builds {#resources}

The engine builds one resource per declaration, read and update, under the declared name, and a deployment tunes it under `resources:` by that name. The same name is what `kernel_settings()` keys its defaults by. An unknown key raises at load, so a misspelled setting is never ignored.

| Declaration | Resource | Key | `resources:` keys |
|----|----|----|----|
| `Array` with `max_len` above 0 | `KVSpec` with a `PagedKVConfig`: a paged KV pool | the array's name | `max_num_pages`, `page_size`, `max_seq_len`, `cpu_offload_pages`, `prefix_cache`, `prefix_cache_salt`, `prefix_cache_tp`, `context_parallel` |
| its `Attend` read (`Causal`, `Window` or `Bidirectional`) | `AttentionSpec` over the pool | the read's key | `backend` (`auto`, `flashinfer`, `dense`, `xpu_paged`), `flashinfer_backend` (`auto`, `fa2`, `fa3`), `decode_tensor_cores`, `decode_fmha` |
| its `Attend` read with `queries=` | `CrossAttentionSpec` over the pool | the read's key | `backend` (`auto`, `flashinfer`), `flashinfer_backend`, `decode_tensor_cores` |
| its `Positions` | `PositionSpec` | `rope`, or `<x>_pos` for an array named `<x>_kv` | none |
| `Array` with `max_len=0` and a `Block` read | `RaggedAttentionSpec`, or `RaggedCrossAttentionSpec` with `queries=`; reads of one kind, nodes and config share the first one's | the read's key | `backend` (`auto`, `flashinfer`, `dense`, `cudnn`, or `sdpa`, which builds no resource), `flashinfer_backend`, `max_segments_per_request`, `max_segments_per_step`, `max_tokens_per_request` |
| `Array` with `max_len=None` and one `Window` read | `BoundedKVSpec`: one slot per request | the array's name | `max_slots` |
| `Value` with tensor fields | `RecurrentStateSpec`: one slot per request and label | the Value's name | `max_slots`, `state_dtype` (with a `GatedDeltaNet`), `prefix_slots` |
| its `GatedDeltaNet` or `Mamba2` update | `LinearAttnSpec` over the Value's pool | the update's key | `backend` (`flashinfer`, the default and the only backend GDN and Mamba-2 run) |
| its `CausalConv` update | runs inside the Value's linear attention | the linear attention's | none |
| `Value` with host fields only | nothing on the device | none | none |
| `Sampler` | `SamplerSpec` | the sampler's name | `enable_logprobs`, `enable_processed_logprobs`, `greedy_capture` |
| `SeqShard` | `SeqShardSpec` | the shard's name | `min_tokens`, `exchange` (`auto`, `none`, `ulysses`, `all_gather`, `ring`) |
| `lora_roots()` | `LoraSpec`, only with a `resources: lora:` block | `lora`; each node's pool is `lora@<node>` | `max_slots`, `max_rank`, `cpu_capacity`, `adapters`, `targets`, `runtime_updates`, `runtime_update_timeout_s` |

`kernel_settings()` reaches a few fields the engine does not pick yet: `splits`, `decode_fmha` and `decode_tensor_cores` on a paged read, `splits` on a `GatedDeltaNet`, `max_segments_per_request`, `max_segments_per_step`, `compile_op` and `workspace_mb` on a `Block` read, and the pool size under the array's name (`max_num_pages`, or `max_slots`).

## Resource notes {#resource-notes}

### Paged KV {#paged-kv}

`PagedKVConfig` carries the model geometry and `max_seq_len`. `max_num_pages` defaults to 2048, and `cpu_offload_pages` is the number of pinned host pages for offload (0, the default, disables it). A pool under a windowed attention keeps only a window of those layers ([sliding windows](#attention)). A declared array on several nodes, as BAGEL's LLM nodes under CFG parallel, takes as leader the node that runs every walk any of its nodes runs (`LLM` for BAGEL), whose pool admits each request; with no such node, or several, each worker's pool admits on its own.

Two lockstep-parallel nodes on one worker (TP, SP or CFG nodes on the same ranks) must not share a resource whose state rank 0 decides for the other ranks outside the step (`supports_eviction`, `lease_cached_prefix` or `page_trail`, as the paged KV cache implements), since the other ranks replay each decision with the next step of the node it was recorded under. The conductor refuses that placement (`Resource.journals_resident_moves`); give each node an array of its own, or place the nodes on different workers.

### Attention over a paged array {#attention}

`backend` selects `auto` (the default: the platform's paged backend, FlashInfer on NVIDIA and AITER on ROCm, see [Kernels](/hardware#amd-kernels)), `flashinfer`, `dense`, `aiter` on ROCm, or `xpu_paged` on Intel XPU. `dense` runs one eager varlen pass over each stream's frozen prefix (gathered from the pages once) and the step's fresh K/V, on FA3 (AITER on ROCm) or, where FA3 has no kernel for the GPU, FlashInfer's ragged prefill (`dense_or_flashinfer`). `flashinfer_backend` picks the FlashInfer kernel generation: `"auto"`, `"fa2"` or `"fa3"`. The engine runs a tiny layout on the chosen kernel when it builds the resource, so a backend the GPU or FlashInfer build cannot run stops the server with a `ValueError` naming it.

`decode_tensor_cores` (default `True`) runs one-token decode rows on FlashInfer's tensor-core kernel; `False` picks the CUDA-core kernel, which can be faster for MHA and narrow GQA (Whisper, Qwen3-ASR and Qwen3-TTS set `False` in `kernel_settings`; measure first). `decode_fmha` (default `False`; Qwen3.5 declares `True`) runs captured one-token decode rows on FlashInfer's trtllm-gen fmha kernel on Blackwell, with no plan per step; a geometry it has no kernel for keeps the paged kernel, with a warning. Eager steps and prompt rows stay on the paged kernels.

A `Window(N)` read is a sliding window: each query attends the last `N` positions, its own included, and the cache keeps about the last `N` tokens of those layers per request, returning the rest to the pool. It needs FlashInfer (`auto` or `fa2`, or `fa3` on SM90; from SM100 `auto` runs `fa2`), causal attention and a paged NHD cache whose other layers a read without a window covers (Command A+). The cache derives its layer groups from its attentions (`derive_kv_groups`); a window at least `max_seq_len` keeps every token. Startup refuses a window over another kind of cache, a layer declared twice, two windows over one cache, a window over every layer, layers no read covers, and cross attention over such a cache. The window's pages hold `page_size × full layers / sliding layers` tokens, which must be whole: unset, the page is the smallest whole one whose pages hold at least 64 tokens in either group, and a YAML `page_size` must be a multiple of `sliding layers / gcd(full, sliding)`. A window is kept in whole pages plus up to one more, so with few sliding layers among many full ones a short window saves little. `max_num_pages` and `cpu_offload_pages` count pages of every layer at the declared `page_size` (128 when unset). Such a cache has no prefix cache yet: its `prefix_cache` goes off (logged at info), and a serving config's `prefix_cache: true` is refused. Forking, serving a node on another instance (replicas included) and handing out `write_slots` are refused too. Under `context_parallel` the window's layers stay whole on every partner ([Context parallelism](#context-parallelism)).

A read with `queries=` is cross-attention over a paged context that is written once and never extended ([Cross-attention](/adding_models#cross-attention-encoder-decoder-models)). Only FlashInfer is implemented. A step whose rows each query one token runs FlashInfer's decode kernel, and `decode_tensor_cores` picks its variant as above.

### Attention within a step {#ragged-attention}

An array with `max_len=0` builds cacheless (ragged) varlen attention over the segments packed into one forward; nothing is paged or carried to the next step. Its config holds the read's heads and head dim (pre-sharding), `sm_scale` (default `head_dim ** -0.5`), `backend`, `flashinfer_backend`, the capture ceilings `max_segments_per_request` (`max_segments_per_step` for a `one_row_per_step` region) and `max_tokens_per_request`, `compile_op` and `workspace_mb`. The ceilings size capture buckets, a memory-against-coverage trade for the deployment; a resource sized per step refuses `max_segments_per_request`. Heads split over the node's TP ranks, or TP × SP over a label a splitting shard lists, which the resource attends by Ulysses ([Sequence and context parallelism](#sequence-parallelism)). `workspace_mb` is the floor of each label's FlashInfer workspace per slot (default `MSTAR_WORKSPACE_BUFFER_MB`, 512), which a larger plan grows; a node with many labels can declare less. `compile_op` and `workspace_mb` are the model's, through `kernel_settings()`; a serving config's `resources:` overrides only the backends and the ceilings.

`auto` (and an explicit `flashinfer`) plan through FlashInfer's ragged prefill wrapper. For a self-attention whose config names neither a backend nor a `flashinfer_backend` (the default; an explicit `auto` is FlashInfer's own choice), `auto` first reads the `ragged_attention` kernel table (`mstar/kernels/tables/ragged_attention/`, [Tuned kernel configs](/adding_models#tuned-kernel-configs)) for the rank's head geometry on the GPU. An eager plan runs the row its longest query segment falls in; a captured bucket runs the row of the layout that first plans it. On `sm_103` the table names cuDNN SDPA (`cudnn`) for the 24-, 30- and 32-head, 128-dim geometries of klein 4B / 9B, Z-Image, Wan2.2-TI2V-5B and LTX-2.5's video self-attention, because under a CUDA graph FlashInfer's `auto` stays on FA2 there. A table bounds sizes no served model has run with a `"*"` row naming `flashinfer`, and the build-time log names the GPU a row was swept on. Without a table entry, `auto` is FlashInfer's own choice.

The cuDNN wrapper runs a layout of equal-length segments, a DiT batch's, as one dense `[segments, S, H, D]` call, self-attention only. A captured one replays only the layout it was planned with, so a captured bucket takes it only when its step declares `ArrayStep(fixed_layout=True)`, as the DiT scaffold's denoise step does on each array; other layouts run FlashInfer. `backend: cudnn` fails at build on a cross-attention, under GQA, in a dtype other than bf16 / fp16, or at a head dim FlashInfer pads. `dense` plans the same layouts into static `cu_seqlens` buffers and runs FA3 `flash_attn_varlen` (AITER on ROCm), or FA3's fixed-length kernel for an eager plan of one non-causal segment on Hopper (and, at head dim 128, per segment when every segment is at least 1536 rows). If FA3 is not importable the factory warns and builds FlashInfer, but that fallback does not cover a GPU or dtype the kernel lacks: `fa3-fwd` 0.0.3 is built for Hopper (`sm_90a`), bf16 only. `backend: sdpa` runs SDPA outside the resources and builds none; it is refused over keys the node's shard splits.

A `Block` read with `queries=` is cross-attention between spans (a DiT's video queries over text keys): each pair is planned as its own layout, pairing each request's query span with that request's key span, and it is never causal. One resource has one head geometry. A label exchanged over SP ranks on its step can't return a log-sum-exp; where keys split, the resource merges the partials itself (LTX-2.5's audio queries over each rank's share of the video tokens, merged by `gather_merge`).

### Bounded KV {#bounded-kv}

An array with `max_len=None` and one `Window(size)` read keeps each request's newest `size` entries in a slot it takes on its first step and keeps: a ring overwritten in place, so a step reserves and releases nothing ([Bounded caches](/adding_models#bounded-sink-window-caches)). The layout comes from the position the step declares, so rows at different positions share a batch and a captured graph. Each query attends the keys at distances `0..size - 1`. The read takes `distance_bias`, `(rows, q_heads, T, size)`, unscaled. The streaming FastConformer (Nemotron VoiceChat's `ENCODER_KV`) is the example.

### Positions {#positions}

Position tracking and RoPE, under `rope` (or `<x>_pos` for an array `<x>_kv`). The declared `Rope` sets `theta`, `scale`, the Llama 3.1 factors (`low_freq_factor`, `high_freq_factor`, `old_context_len`), `interleave` for GPT-J pairing, `rotary_dim` for a partial rotation, and `table_dtype` for a cos/sin table built once (GLM-5.2 uses float32), which `cos_sin_table` hands to a kernel that rotates inside a larger fusion. On CUDA that table needs a `rotary_dim` that is a multiple of 32 with NeoX pairing, of 16 with GPT-J pairing. A model with learned position embeddings declares `Positions()` for the counter and never applies RoPE.

`Rope(longrope=LongRoPE.from_hf(config))` (Phi-3, Phi-4-mini, Phi-4-multimodal) builds a short and a long table. A request whose `MAX_POSITION_KWARG` (set by `process_prompt`; a client's value is dropped) passes `original_max_position_embeddings` rotates with the long one for its whole life. Set it to the length the reference picks its table by: the prompt's for Phi-3 and Phi-4, not prompt plus `max_tokens`. The long table is named in the request's prefix keys, and explicit position ids are refused under it.

### Sampler {#sampler}

A sampler with its own per-request parameter buffers, philox stream, and optional seen-token mask. `penalty` and `min_p` declare capabilities, not intentions: each selects which kernel variant is recorded into the captured graph. Whether the penalty runs on a given step is decided from the `repetition_penalty` values of the resident requests. See `SampleSettings` under [Per-request settings](/adding_models#per-request-settings) for `enable_logprobs`, `enable_processed_logprobs` and `greedy_capture`.

### Recurrent state {#recurrent-state}

A `Value` with tensor fields is fixed-size per-request state that carries between steps (a conv tail, a gated-DeltaNet or Mamba layer's state, a streaming encoder's caches): one slot per request and label, `labels` naming every label a request's steps address or fork into, so that admission reserves a slot for each, and one copy per declared layer. `max_slots` counts the sink unless the pool disables it; a value that leaves no slot for a request is refused at startup. Slot 0 is the sink that padding rows address.

A `GatedDeltaNet` or `Mamba2` update builds a linear attention planned against the Value's pool: gated DeltaNet or Mamba-2. A layer calls gated DeltaNet through `causal_conv` and `gated_delta_net`, and Mamba-2 through `causal_conv` and `mamba2`, so the layer never names a block of the pool. The shared layer is `ParallelGatedDeltaNet` (`mstar/model/components/distributed/`). Gated DeltaNet stores `state` K-last, in fp32 unless the decode kernel takes the declared dtype.

### Sequence shard {#sequence-shard}

Whether a step's tokens split over the node's sequence-parallel ranks, and each listed label's per-rank ranges. Its step is the node's segments, so the model declares no step for it, and the model brackets its layer stack with `scatter` and `gather` on the shard's handle. See [Sequence and context parallelism](#sequence-parallelism).

### LoRA pool {#lora-pool}

Per-request LoRA adapters on the node's LoRA-capable linears: a pool of device slots, a pinned host tier, and the per-step addressing the LoRA kernels read. It is built from the model's `lora_roots()` ([Per-request LoRA adapters](/adding_models#per-request-lora-adapters)) only when the serving YAML has a `resources: lora:` block, as one `LoraSpec` over every node adapters reach, with a pool per node.

- **Targets.** `LoraTarget` gives the unsharded linear's shape and its TP split. Column-parallel: A replicated, B split by output rows per slice (a slice with fewer heads than ranks is replicated, as `QKVParallelLinear` does with K/V). Row-parallel: A split along the input, B replicated, and the delta added to the partial output before the all-reduce, so LoRA adds no collective. `layers` restricts a target to some layers, `slice_packs` names a checkpoint tensor that packs several slices (Qwen3.5's delta-net `in_proj_qkv`), `slice_align` a per-rank padding, and `parallel="none"` a target whole on every rank. `experts=E` is a stacked MoE parameter: each (token, top-k) row runs its slot's factors for the routed expert, addressed by `(slot - 1) * E + expert`, on the fused-MoE grouped GEMM. Experts targets are opt-in (`LoraSpec.dropped_targets`, served by naming them in `targets:`), a spec serves at most `992 // E` slots (7 at 128 experts) and refuses more, and experts split by expert parallelism are refused at deployment validation and at bind; serve them under TP.
- **Kinds and rows.** `kind="embedding"` is a token embedding: `in_features` is the vocabulary and the shrink a gather of A's column per token (PEFT's `lora_embedding_A` / `_B`); an id outside the vocabulary adds nothing. `per_segment` is one row per segment and `token_fold=k` one row per `k` tokens.
- **Checkpoints.** Adapters are validated from the read that pins their digest: modules map to targets, shapes fit (an adapter for another model size is a 400), and a conv adapter whose kernel is its stride flattens to the linear. DoRA (`lora_magnitude_vector`, `dora_scale`), `modules_to_save`, trainable tokens and bias LoRA are refused by name.
- **`targets:`.** A YAML list keeps a subset of all the declared targets, experts ones included (dropping vocabulary-sized ones saves slot memory), and an adapter touching a dropped target is refused; a list that keeps none is an error. Without it, a deployment with `runtime_updates` off keeps the targets its configured adapters touch, read once at startup (`resolve_lora_adapters`) so every worker builds the same pools, and an adapter it cannot read fails the deployment. One with `runtime_updates` on keeps every target but the experts ones. A node left with no target gets no pool.
- **Requests.** A request names an adapter in the `lora_adapter` kwarg, which the OpenAI `model` field maps onto, or which `process_prompt` sets ([Cross-request prefix reuse](/adding_models#cross-request-prefix-reuse)). The API server refuses an adapter it does not serve with a 400, and the conductor one with a runtime load or unload in flight with a 409. Adapters are checked when registered (rank within `max_rank`, declared targets, shapes), not per request, and each is prefix-cached in its own namespace ([Prefix cache](#prefix-cache)).
- **Capture.** A node serving adapters captures and compiles the same buckets as one that doesn't. A capture plans every row on the zero adapter and a replay writes each row's slot into the recorded buffers, so one graph serves any mix of adapters. The kernels are the custom ops `mstar::lora_shrink`, `mstar::lora_expand_` and `mstar::lora_experts_apply_`, single nodes to `torch.compile`. The pool is a [lean resource](#lean-captures): a step whose rows name no adapter replays a twin with no LoRA kernel. The choice reads only which adapter each request named, so the node's `cg_key_info` and `declare_step` state only its own key.
- **dtype and backend.** Slots take the node's compute dtype (`autocast_dtype`); a node outside autocast sets `LoraSpec.dtype`. `backend` is `"triton"` (the default on CUDA) or `"torch"` (the reference, the default elsewhere). Registration is process-wide: once any pool registers the Triton kernels, every pool on CUDA runs them.

Slot 0 is the zero adapter that base-model rows and padding rows address. A request takes its adapter's slot at its first admit and holds it until removed; a miss loads from the host tier into a free slot, or the unheld slot released longest ago. A request whose adapter can't get a slot, or whose host copy is still being read, waits at the runner's admission in arrival order (`LoraAdapterPool.ask` / `reserve`), holding no KV pages. Only the first waiting request is admitted, so a cold adapter is not starved; on one GPU that also holds back newer base-model requests on the node until a slot drains, while under TP they go past it. Neither wait arises while the adapters in rotation fit in `max_slots`. An adapter with nothing for a pool's targets takes no slot there. Files are read on the pool's reader thread from the ingest of a request that names the adapter, and an admit never reads a file. The pool admits and plans on the GPU thread in step order, and its device writes go on the forward stream.

Under TP each rank keeps its own pool and reaches the same slot decisions from the same admit order, with nothing journalled from rank 0; the LRU clock counts admits. A disk read can fail on one rank only, so the ranks agree on each adapter's copy (in, being read, failed) with a gloo all-reduce per admit that installs adapters, and every rank installs it or refuses the request. In steady state there is no all-reduce.

Runtime loads and unloads (`/v1/load_lora_adapter`, `/v1/unload_lora_adapter`) reach each worker as a control message from the conductor. A load only reads the adapter into the host tier; an unload only stops new requests from naming it, and the host copy is dropped once no live request names it. Nothing per model is needed.

### Prefix cache {#prefix-cache}

A model opts in through `PrefixKeys` and `checkpoint_path` ([Cross-request prefix reuse](/adding_models#cross-request-prefix-reuse)). The rest is the resources'.

On a node with a recurrent state pool, a hit is cut to the longest snapshot of that state the pool holds, since a recurrent layer can't skip tokens. The deployment gives the pool `prefix_slots` under its `resources:` key; each snapshot slot costs as much as a request slot.

- A prefill snapshots at its last page boundary before its end (a resend's KV hit always recomputes the last page), and at its KV hit's last boundary when that is past what it restored, so a shared prefix is served from the third request that shares it. A step longer than the largest captured bucket checkpoints less often.
- A chunked prompt keeps each chunk's last boundary; the pool declares a page as its `chunk_alignment`, so chunks are cut whole pages long.
- A decode step that ends a page snapshots there, replacing the request's previous decode snapshot, so a later turn that re-sends the reply restores it.
- Snapshots are keyed by the KV chain's key at their page. A full pool evicts the least recently used snapshot no request holds, decode snapshots before prompt ones.

Snapshots stay off without `prefix_slots`, above one rank, without a linked KV cache on every node of the pool, or when that cache's `prefix_cache` is off or kept shut (a model with no checkpoint and no salt). Every cache on the node of a pool without snapshots then stays shut, and the engine logs which pool kept it shut. `opening_prefix_caches` in `mstar/engine/resources/kv/config.py` is that rule, evaluated once before any resource is built; routing and the API server's prompt hashing use the same answer per rank (`prefix_caches_by_rank`). A resource takes part through its spec: `NodeResourceSpec.keeps_prefix_cache`, and `restores_prefix` for state a hit must restore.

A request on a LoRA adapter keys its pages from a root that names the adapter's weights: a SHA-256 over every module's A, B (dtype and shape) and alpha, computed at registration (`adapter_prefix_root` in `mstar/engine/resources/lora/identity.py`) and carried as `KVReqConfig.prefix_root`. The same tokens under two adapters, or under an adapter and the base model, never share pages; two names for identical weights do. A name registered again with other weights misses the old pages, and a request selected under the old weights (`LoraReqConfig.digest`) is refused at ingest.

A resource whose KV differs per request for the same tokens (a LongRoPE table picked by prompt length) says so in `NodeResourceSpec.prefix_variant(model_kwargs)`: opaque bytes, from the same kwargs its `request_config` reads, or None. The data worker folds them into the root after any adapter's, in declaration order (`variant_root` in `mstar/engine/resources/kv/keys.py`).

### Admission hooks {#admission-hooks}

A resource whose capacity can run out before a request starts, and that the request holds until it is removed (KV pages, recurrent-state slots, sampler rows), answers through the admission hooks on `Resource`. The runner's `Admission` keeps one arrival order across resources, and a request takes everything it asks for or nothing. Capacity one step takes and gives back goes through `admit` and `rollback_admit` instead.

- `ask(rid, node_name, graph_walk)`: `ASKS` while the request needs this capacity to start, None when it needs none, or a failing outcome when it can never fit.
- `reserve(rid, node_name, graph_walk, published)`: takes it and returns None, or returns a mark of what it didn't fit against.
- `unreserve(rid)`: gives back what `reserve` took, when another resource didn't fit.
- `grew_since(mark)`: whether a request blocked at `mark` may fit now; the runner retries a blocked queue only then.

A request is admitted once it is first in every queue it waits in. A resource that overrides `reserve_past(rid, node_name, graph_walk, published)` lets a later request pass a first one that can't start, taking only capacity the first doesn't need, or returning a mark, after which the runner tries the passing request again only once `grew_since` that mark. The runner calls it only while the first request can't start. A resource that doesn't override it keeps strict order, and a request waiting in its queue can't pass anywhere. The KV cache overrides it, and a request it has moved others to make room for may start wherever it stands in its queue.

### Routing across data-parallel replicas {#routing}

When a node group has several replicas, the conductor sends each new request to the replica where it is cheapest ([Serving](/serving)). A resource takes part through its spec, so models declare nothing.

`NodeResourceSpec.routing_mirror(ctx)` returns a `RoutingMirror` or `None` (the default). `ctx` (a `RoutingContext`) gives the replica count, the walks of the worker graphs holding the spec's nodes, the resource's keyed labels and the walks that key them, and whether every replica opens its prefix cache. A mirror is conductor-side bookkeeping of the resource's rules, so its module imports no kernels. Each method gets the request's `ResourceReqConfig`:

- `facts(config)`: the request's `RoutingFacts` per replica, named counts such as `work` (prompt positions) and `kv_hit` (those predicted cached). The router sums every mirror's facts per replica and prices them with `routing_cost` in `mstar/conductor/routing.py`, one term per `routing_weights` key.
- `add_request(config, replica)`: records the placement at dispatch and returns a handle.
- `remove_request(handle, ran)`: releases it; `ran` says whether a pass came back on the resource's node groups.

A new resource adds its fields to `RoutingFacts`, its mirror, and its term to `routing_cost` and `RoutingWeights`; `ReplicaRouter` changes only for fields that are not additive counts, or for a mirror that reads a model declaration other than the KV ones, which then becomes a `RoutingContext` field that `ReplicaRouter` fills. `KVSpec` with a `PagedKVConfig` is the one implementation: its mirror runs the worker's `PrefixIndex` and `PageArena` per replica, without storage, and exists only where a walk keying the cache runs and `opening_prefix_caches` opens it.

### Lean captures {#lean-captures}

A resource whose kernels can be left out of a step whose rows all allow it sets `Resource.lean_capture`, answers `lean_for(request_ids)` from state every lockstep rank sets alike (its ingests), and names the kinds of capture that get its twin (`lean_captures`). Beside each bucket whose step drives such resources, the engine captures a twin per set of them (`BucketKey.lean`). A step replays the twin of every resource its rows let run lean, else one with fewer (largest set first, ties in declaration order), else the plain bucket, and names the set in `StepContext.lean`, eager steps included. A resource whose callers read its plan inside the forward also overrides `Resource.outside_step`, entered around compile warm-ups outside any step. Twins are captured after every plain bucket; one left out (under the capture budget, say) is logged at INFO, and its steps replay the plain bucket. Lean resources: the LoRA pool, for steps whose rows name no adapter, in every kind of capture; and a sampler (`SamplingReqConfig`), for all-greedy steps, in batched captures. A model declares nothing for these.

## Sequence and context parallelism {#sequence-parallelism}

A node's `sp_size` ranks share each of its steps, along two axes:

1.  **Per step, the tokens are split or copied.** A sequence shard on the node decides, every step: split, each rank runs the token-local layers (norms, MLPs, projections) on its share of each listed label (contiguous, or on a ring node striped by KV position); or copied, every rank runs them all. Without one, every step is copied.
2.  **Per paged KV pool, stored K/V is split by head or by position.** By head (the default) over the node's `tp * sp` ranks; by position with `context_parallel: true` (below), heads over TP.

Each attention resource derives what it does from the two and the shard's `exchange` (below); the model writes no exchange (a ragged attention's Ulysses follows from the labels it plans):

| Tokens / storage | By head | By position (`context_parallel`) | Cacheless (ragged) |
|----|----|----|----|
| Copied | head slice: this rank's heads of q, k and v, write and attend, gather the heads | each rank attends its slots, partials merged (below) | heads over TP; over a label the shard lists on a splitting node, a head slice |
| Split | Ulysses: one all-to-all from split tokens to split heads, write and attend, one back | by the shard's `exchange` (below): `all_gather`, one gather of every rank's q, k and v, attend as a copied step, keep this rank's rows; or `ring`. With `auto`, the node's steps run copied | Ulysses over a label the resource plans; any other split label refused at its first split step |
| Cross, split queries | n/a | n/a | each rank's queries over every key |
| Cross, split keys | n/a | n/a | each rank's partial over its keys, merged by log-sum-exp (`gather_merge`) |
| Cross, both split | n/a | n/a | refused at load |

Splitting is declared in four places:

- `SeqShard(name, nodes=, labels=, walks=)` names the label whose tokens split, on its reads' axis: axis 0 cuts packed tokens or a segmented row into contiguous ranges, axis 1 cuts each row of a `[B, S, ...]` layout alike (`packed=False`). Other walks than `walks` plan copied. A step splits only when it isn't one token a row, its listed tokens reach `max(sp_size, min_tokens)`, and every listed label has at least `sp_size` tokens (rows, on axis 1). `min_tokens` (default 0) and `exchange` (below) are `resources:` overrides. A captured step decides from its bucket's size, so capture and replay agree; where a resource splits eagerly only (`NodeResourceSpec.splits_eagerly`), the shard's floor sits one past each walk's largest captured bucket (`min_tokens` only raises it). The shard must cover every node of the attention resources that depend on it, and a KV pool can't depend on two shards. MiniMax-H3's video decoder writes a shard by hand with `exchanges=False` (no op mixes the label's units, so nothing exchanges and a rank may get none), reads `shard.split_range(label)` and gathers with `shard.gather` (`mstar/model/minimax_h3/submodules.py`); such a shard is refused beside an attention that takes split steps.
- The model declares **no step** for the shard: its step is the node's segments and combined labels (`Resource.steps_from_segments`), at any SP size. A step that declares no segments has no shard plan, and the attention resources refuse it, even on one GPU. The diffusion scaffold's step holds each label's segments once, however many arrays attend them.
- The forward **brackets** its layer stack with `scatter(shard, *xs)` before (`dim` defaults to the shard's axis; `None` passes through) and `gather(shard, x)` after. `split_range(shard)` gives this rank's `start`, `count` and every rank's `counts` where the step splits, else `None` (Wan2.2's timestep runs, MiniMax-H3's rope rows). Everything between them runs on this rank's tokens. Both are the identity on a copied step, at one SP rank and outside a step, and on SP ranks each breaks the graph once. LTX-2.5 brackets its DiT in the denoise step (`mstar/model/ltx2_5/submodules.py`), Wan2.2 and MiniMax-H3 inside the DiT forward, Cosmos3 after its whole-sequence prologue (`mstar/model/cosmos3/components/transformer.py`), and Qwen3.5 around its LLM stack, gated delta rule layers included (`Qwen3_5ForCausalLM.forward`).
- Attention goes through the array's handle. A state op that fuses the K/V write (Qwen3-Omni's `qk_norm_rope_table_attend`) runs its reference wherever the step's read exchanges (`AttentionManager.step_exchanges(label)`): a split label, and every step over KV stored by head. A cacheless self-attention over a listed label runs Ulysses with nothing declared. Both are no-ops without a shard, or with one that never splits (`SeqShardSpec.splits`), so one declaration serves every deployment shape. `backend: sdpa` is refused over split keys.

**Recurrent and sliding-window layers** take split steps through their own resources; the model writes only the bracket. Each resource's state is stored by head, by position (`context_parallel`) or copied (`NodeResourceSpec.storage`), and a copied resource takes its own exchange on a splitting shard, whatever `exchange` says:

- A **recurrent pool** (GDN, Mamba-2) is copied, so decode needs no collective. On a split step the conv runs from the earlier ranks' last inputs (`conv_halo`, one all-gather a layer), and every rank writes every row's final window. Prompt rows take `ulysses` where each TP rank's heads split `sp_size` ways (one all-to-all to a block of heads and one back; for Mamba-2 it saves memory, not time), else `state_passing` (each rank hands its state on in one fixed-size gather). `state_passing` and Mamba-2's split are tested on CPU only and no in-tree model uses them. Both run eagerly, so the shard's floor sits above the largest captured bucket. Prefix snapshots stay off above one rank.
- A **sliding-window** attention over a pool stored by position keeps its window layers whole on every SP rank (`PagedKVConfig.placed_groups`) while full layers stripe: copied steps attend as on one rank, split steps gather the step's keys (`kv_gather`) eagerly, and each window page must split `sp_size` ways. Tested on CPU only, over FlashInfer's reference.

Every resource of a splitting node must support split steps (`Resource.supports_split_steps`): the KV pool, paged FlashInfer and dense attention, ragged self and cross attention, positions, the sampler, and the recurrent pool with its GDN and Mamba-2 resources. MLA, DSA, KDA, flex and XPU attention don't, and the engine refuses them on a splitting node at load. Before a worker starts (and again at load) the conductor refuses:

- a node on SP ranks that neither splits its steps nor places its pools by position;
- a shard on axis 1 over a pool stored by position, and a linear layer under axis 1 or a ring;
- a head-stored pool whose query and KV heads per TP rank don't divide by `sp_size`;
- a ragged Ulysses attention whose heads don't divide by `tp * sp`, or beside a ring;
- SDPA over split keys, and a ragged cross-attention under axis 0 or `exchanges=False`;
- a `state_passing` linear layer (not Mamba-2) whose key and value head dims differ, at `sp_size` 3 or more;
- a `kv_gather` attention under a ring, and a window page that doesn't split `sp_size` ways;
- expert parallelism.

At warmup the engine also refuses piecewise captures, a capture replayed under listed and unlisted walks, and a packed capture of a listed walk unless the shard lists one label on axis 0. Each attention resource of a splitting node logs at load how it takes split steps.

### Choosing the exchange {#choosing-the-exchange}

`exchange` in the shard's `resources:` block picks how split steps reach the node's paged attentions. `auto` (the default) runs Ulysses over KV stored by head, and runs steps copied over KV stored by position, so such a node splits only where the deployment opts in with `all_gather` or `ring`. A value the storage can't take fails at load, at any SP size. Copied steps keep the storage's own path. Each row assumes a shard and `sp_size` above 1:

| `exchange` | KV stored | Split steps | Copied steps | Pick it when |
|----|----|----|----|----|
| `auto` / `ulysses` | by head | Ulysses all-to-all | head slice | q and KV heads per TP rank divide by `sp_size` (Cosmos3; LTX-2.5, Wan2.2 and MiniMax-H3's DiT, which have no paged pool, by their ragged attentions over the labels their shards list) |
| `auto` / `none` | by position (`context_parallel`) | never: the node runs copied, as one without a shard | partials merged | KV capacity alone (DCP), no token split |
| `all_gather` | by position | gather q, k and v, attend as copied, keep own rows | partials merged | long prompts where one KV head per TP rank can't split by head (Qwen3-Omni's Thinker on TP4 x SP2) |
| `ring` | by position | striped pass-Q ring, eager only | partials merged | attention is the step's peak memory (below); not beside a recurrent layer or a `kv_gather` attention |
| `none` | by head | refused at load: the SP ranks would only share heads | n/a | never; use TP |

The copied resources (recurrent layers, sliding windows over KV stored by position) pick their own exchange, as listed above: a recurrent layer takes `ulysses` where its heads (and Mamba-2's B/C groups) per TP rank divide by `sp_size`, as Qwen3.5's do, and `state_passing` otherwise, whose hand-off doesn't grow with the prompt but isn't faster at `P = 2`.

`ulysses` over KV stored by position, and `all_gather` or `ring` over KV stored by head, are refused. A shard that never splits (`none`, or `auto` over KV stored by position) makes the node plan every step copied, so it takes what a node without a shard takes (expert parallelism, say).

### Ring {#ring}

`exchange: ring` stripes each split step's tokens over the SP ranks by KV position: rank `r` takes the tokens at positions `x % P == r`, exactly the ones whose K/V it stores, so nothing moves on the write. Each layer then runs `P` rounds: rank `r` sends its queries to rank `r + i`, attends rank `r - i`'s over its own slots (stored context and the step's tokens in one call), sends the partial back, and merges in fp32. Hops are synchronous, and only the `flashinfer` backend plans it (another is refused when the attention is built). Ring is eager only: steps that could split run eagerly and the rest keep their graphs. A step that combines listed labels into one plan (Cosmos3's batched CFG) is refused when it plans on a ring node.

A step's peak memory is its resident tensors plus the larger of its attention and MLP (or MoE) phase. All-gather's attention phase holds the whole step's q, k and v and `P` partials per query; ring's holds this rank's tokens and two fp32 copies of their result. So ring lowers the peak only once attention outgrows the MLP phase: by an estimate from allocation sites, not a measurement, about `P = 4` for the Qwen3-Omni Thinker, sooner for dense models. Ring merges `P` bf16 partials per query, so its greedy output can differ from the copied path's. Chunked prefill stays off on SP ranks either way.

### Context parallelism {#context-parallelism}

`context_parallel: true` on a paged KV pool stripes each page's slots over the ranks that would otherwise store the same KV heads: slot `s` lives on partner `s % P`, page ids stay the same on every rank, and each rank holds `page_size / P` slots a page. Attention runs on each rank's slots and merges the partials across the partners exactly (`mstar/engine/resources/context_parallel.py`). The model declares nothing.

- **TP mode (no SP ranks).** The partners are the TP ranks sharing a KV head, `P = tp / num_kv_heads`, so TP must be a larger multiple of the KV heads. They are the contiguous blocks `kv_head_replicas` (`mstar/distributed/utils.py`) gives, as `QKVParallelLinear` loads them; a model that shards K and V itself must match. Each placed layer exchanges queries and partials over the TP group. TP mode chunks prompts as without placement.
- **SP mode.** The partners are the node's SP ranks, `P = sp_size`, and heads shard over TP alone. Every paged pool of the node must set the key. Without a shard every layer but attention runs copied across SP, so prefer TP mode where it applies; with `exchange` `all_gather` or `ring`, long steps split their tokens too. Chunked prefill stays off (`_unchunkable_nodes`), so a prompt prefills in one step.

A page's tokens (`page_size`, 128 when unset) must divide by `P`; the conductor checks these rules against `node_groups` before it starts a worker. `max_num_pages` counts logical pages, so raise it by `P` to use the memory placement frees (the pool logs its bytes per rank). Every resource over the pool must support placement, or loading fails naming the one that doesn't: FlashInfer attention (`auto`, `fa2` or `fa3`), RoPE positions and the recurrent state pool do; dense, flex, XPU, block-causal and MLA attention, cross-attention and DSA don't, and a ring or bounded KV pool can't set the key. An SP-placed pool that prefills on `fa2` warns at startup (an explicit `fa2`, or `auto` below SM90 and from SM100; `auto` on SM90 prefills on `fa3`). A sliding window stays whole on every partner in pages of `1/P` its unplaced tokens, while the full layers stripe; a window at least `max_seq_len` is refused there. `splits` and `decode_fmha` are ignored over a placed pool (and `decode_tensor_cores` in TP mode, which decodes on tensor cores), a node over one plans on the host (`resident_planning`), and a node that captures a combined-label step (classifier-free guidance) at a batch size above 1 is refused.

A step of one token a row attends the pages after its KV write. Any other step attends its stored context on the pages and its own tokens from the `k` and `v` the layer adds, so a state op's fused kernel runs its reference there. In SP mode, rank `r` attends the step's own tokens in *zigzag* chunks `r` and `2P - 1 - r` of each row's `2P` (`zigzag_rows`), which balances the causal work, and merges them into its context partial before the gather.
