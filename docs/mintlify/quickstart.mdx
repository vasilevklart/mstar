title: "Quickstart"
description: "Install M* from source, serve BAGEL on one GPU, and send it a first request."
---

You need Linux, one NVIDIA GPU, Python 3.12, [uv](https://docs.astral.sh/uv/), [rustup](https://rustup.rs) and a C/C++ compiler. [Installation](/installation) has the details. Without Rust, install rustup first:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
. "$HOME/.cargo/env"
```

## Install and start a server {#start-a-server}

```bash
git clone https://github.com/mstar-project/mstar.git
cd mstar
uv venv --python 3.12 --seed
source .venv/bin/activate
uv pip install --torch-backend=auto -e ".[bagel]"

# Rust graph runtime and HTTP frontend (needs rustup)
uv pip install maturin
maturin develop --release -m rust/Cargo.toml
cargo build --release --manifest-path rust/server/Cargo.toml

mstar serve bagel
```

Leave it running. The first start downloads `ByteDance-Seed/BAGEL-7B-MoT` (about 30 GB, into `$HF_HOME`, default `~/.cache/huggingface`), then compiles the model and builds FlashInfer kernels before it listens on port 8000. On 1x H200 (2026-11-27), with the weights already downloaded, that took 8.6 minutes, and a restart that reused the compile caches took 68 seconds ([Startup time](#startup-time)).

## Check health {#check-health}

The `✓ mstar serving 'bagel'` line prints when startup begins, not when the server is ready. In a second terminal:

```bash
curl http://localhost:8000/health
```

The server is ready when this prints `{"status":"healthy"}`. Until then the connection is refused; errors show in the first terminal.

## Send a request {#send-a-request}

In the second terminal, activate the same `.venv`, then run:

```python
from mstar import MStarClient

client = MStarClient("http://localhost:8000")
print(client.chat("What is the capital of France?").text)
```

Stream the answer:

```python
from mstar import MStarClient
from mstar.client import TextChunk

client = MStarClient("http://localhost:8000")
for event in client.chat("Tell me a short story.", stream=True):
    if isinstance(event, TextChunk):
        print(event.text, end="", flush=True)
print()
```

The native `/generate` endpoint takes form fields. `output_modalities` depends on the model: `text` here, `audio` for speech models, `image` for image models. The reply is JSON with each output base64-encoded under `outputs`; this decodes the text:

```bash
curl -s http://localhost:8000/generate \
  -F text='What is the capital of France?' -F output_modalities=text -F streaming=false |
  python -c "import base64, json, sys; print(b''.join(base64.b64decode(c['data']) for c in json.load(sys.stdin)['outputs']['text']).decode())"
```

Without `streaming=false` the reply is an NDJSON stream with one base64 chunk per token ([Clients](/clients#native-generate)).

For the OpenAI-compatible routes, install the client:

```bash
uv pip install openai
```

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="none")
resp = client.chat.completions.create(
    model="bagel",
    messages=[{"role": "user", "content": "Give me one fun fact."}],
)
print(resp.choices[0].message.content)
```

[OpenAI coverage](/reference/http-api#openai-coverage) lists the routes each model serves.

## Serve another model {#another-model}

Install the model's extra, then serve its key:

| Task | Key | GPUs | Extra |
|---|---|---|---|
| Text and image chat | `qwen3_5_4b` | 1 | `all` |
| Omni: text, image, audio and video in; text and speech out | `qwen3_omni` | 2 | `qwen3_omni` |
| Text to speech | `kokoro` | 1 | `kokoro` |
| Speech recognition | `whisper_large_v3_turbo` | 1 | `asr` |
| Image generation | `flux2_klein` | 1 | `flux2_klein` |
| Video generation | `wan22` | 1 | `wan22` |
| Robot policy | `pi05` | 1 | `pi05` |

```bash
uv pip install --torch-backend=auto -e ".[kokoro]"
mstar serve kokoro
```

[Supported models](/models#matrix) lists all 61 keys. Some weights are gated on Hugging Face, for example the PaliGemma tokenizer that `pi05` loads and the `ltx2_5` checkpoint. Accept the license on the model page, then `export HF_TOKEN=<your token>` before `mstar serve`. A token also avoids Hugging Face's lower rate limit for unauthenticated downloads, which the server warns about at startup.

## GPUs, port and API key {#options}

```bash
mstar serve qwen3_omni --gpus 0,1 --port 9000
```

`--gpus` sets `CUDA_VISIBLE_DEVICES` and must expose as many GPUs as the config uses.

By default the server listens on all interfaces (`0.0.0.0`) and accepts requests without a key. To require one:

```bash
export MSTAR_API_KEY=replace-with-a-secret
mstar serve bagel
```

`MStarClient` reads `MSTAR_API_KEY` from the environment; an OpenAI client takes it as `api_key`. `--host 127.0.0.1` keeps the server local. [CLI reference](/reference/cli#serve) lists every flag.

## Startup time {#startup-time}

<Note>
Before it listens, the server loads the weights, compiles and captures the model, and runs any warmup requests in the config. On a cold cache this is the long part: of BAGEL's 8.6-minute first start above, 8 minutes went to compiling, up to 3.7 of them to FlashInfer JIT builds, and the log went quiet for up to 2.6 minutes at a time; the first request then took 0.15 seconds. Compiled kernels are cached under `~/.cache/mstar` and `~/.cache/flashinfer` and reused on later starts. `mstar serve bagel -O0` skips compile tuning for the fastest start. See [Cold start](/cold-start).
</Note>
