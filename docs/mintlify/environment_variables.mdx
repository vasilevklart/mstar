Variables M\* reads from the environment, by the part of the system that reads them. Variables the launcher sets for its own child processes are in [Set by the launcher](/environment_variables#set-by-the-launcher); tests and debugging checks are in the [last section](/environment_variables#tests-and-debugging).

## Communication {#communication}

| Variable | Default | Meaning |
|----|----|----|
| `MSTAR_WIRE_CODEC` | `msgpack` | How messages are encoded on every communicator edge: the typed, language-neutral encoding in `mstar/communication/wire.py`, so an edge can end in a Rust process. `pickle` fails at startup. Upgrade every process of a deployment together. |
| `MSTAR_ZMQ_TRANSPORT` | the constructor's protocol | Overrides the communicator protocol (`IPC` or `TCP`) for a process, for example to run entities on separate hosts. |
| `MSTAR_ZMQ_TCP_HOST` | `127.0.0.1` | Host used to build peer endpoints when the protocol is `TCP`. |
| `MSTAR_ZMQ_TCP_BASE_PORT` | `19000` | Base of the entity-to-port map: `api_server` is the base, `conductor` base+1, `worker_<rank>` base+100+rank. |
| `MSTAR_DEPLOYMENT_TOKEN` | random per launch | Namespaces the SHM tensor files and arena segments, so no two launches share names, also across containers that share `/dev/shm` (`--ipc=host`). The API server mints one per launch and the conductor and workers inherit it. Set it only when a launcher starts a deployment's processes separately: the same value in all of them, and a new value per launch. |
| `MSTAR_KV_SHM_DIR` | `/dev/shm`, or `/tmp` if unavailable | Base directory for host-staged KV snapshots when remote KV transfer uses SHM. Each deployment makes a private child directory and holds a lock file there; startup removes this user's directories that no live process holds. Workers that share snapshots must see the same filesystem. On a filesystem whose `flock` is per node (GPFS), do not point deployments on different nodes at one directory. |
| `MSTAR_SHM_ARENA_SEGMENT_MB` | `256`, less on a small or crowded `/dev/shm` | Size of each arena segment. An arena grows one segment at a time and segments never move. A segment's pages are committed when it is created, so the whole segment counts against `/dev/shm`, as do spill files. A segment `/dev/shm` cannot hold counts as a full arena, so sends spill. |
| `MSTAR_SHM_ARENA_MAX_SEGMENTS` | `32`, fewer on a small or crowded `/dev/shm` | Segments per entity (each worker and the data worker has an arena), so node-wide use can reach segments x size x entities; check `df -h /dev/shm`. With neither this nor `MSTAR_SHM_ARENA_SEGMENT_MB` set, the API server splits the free space among the arenas and logs the sizes. An entity with under 16 MiB, or on ROCm or XPU, sends tensors as files. Set by hand, startup fails if one entity's ceiling exceeds `/dev/shm`. |
| `MSTAR_SHM_ARENA_FULL_TIMEOUT_S` | `30` | With `MSTAR_SHM_ARENA_SPILL=0` only: how long a send waits on a full arena before it fails. |
| `MSTAR_SHM_ARENA_SPILL` | `1` | At the segment cap, send the tensor as a file instead: slower, never fails. `0` makes a send wait and then fail, which only helps where another thread drains the consumers' acknowledgements (the API server); a worker would wait on itself. An entity without an arena spills every send either way. |
| `MSTAR_SHM_ARENA_SPILL_AFTER_S` | `0` | Grace before spilling, for deployments where another thread frees slots concurrently. `0` spills at once. |
| `MSTAR_SHM_ARENA_PIN` | `1` | Page-locks (`cudaHostRegister`) each mapped segment on both sides, so copies through it are asynchronous at pinned bandwidth. `0` uses pageable copies. |
| `MSTAR_SHM_ARENA_PIN_MAX_MB` | `4096` | Pinned host memory per process. A consumer pins its peers' segments too, so node-wide pinned memory is about this times the number of entities. Segments past the budget stay unpinned and copy without overlap. |
| `MSTAR_SHM_ARENA_GATHER_MAX_BYTES` | `16384` | Largest item a consumer gathers with others of the same shape, dtype and segment into one pinned buffer and one host-to-device copy, instead of one copy per item. `0` turns the gather off. |
| `MSTAR_SHM_ARENA_GATHER_WORDS_MAX_BYTES` | `512` | Up to this item size (8-byte aligned) the gather indexes 8-byte words in one pass; larger items copy one slice each. |
| `MSTAR_SHM_ARENA_SLOT_TTL_S` | `0` | Reclaims a slot left behind by a request aborted after staging but before every consumer acknowledged it, once the slot is this old. Use at least twice the request timeout, so it cannot race a real reader. `0` turns it off. |
| `MSTAR_SHM_ARENA_STATS_INTERVAL_S` | `60` | With `--log-stats`: how often each arena logs its occupancy and fragmentation. |
| `MC_TRANSFER_TIMEOUT` | `30` | Mooncake's variable. M\*'s TCP and RDMA tensor reads also give up after this many seconds plus 1 ns per byte, with `Mooncake read timed out after N s`. Read as an integer, at least 5. |
| `NCCL_SOCKET_IFNAME` | `lo` | NCCL's variable. Every worker runs on the conductor's host, so the conductor sets `lo` for its workers. A value you set, or a set `NCCL_SOCKET_FAMILY`, is kept. |
| `NCCL_GRAPH_REGISTER` | `0` | NCCL's variable. Workers on CUDA set `0` unless you set it: with buffer registration on, Cosmos3 SP4 with batched captures produced wrong images. |
| `GLOO_SOCKET_IFNAME` | `lo` | PyTorch's variable for the Gloo groups. The conductor sets `lo` for its workers unless you set it. |

## Models {#models}

Per-model knobs, read when the model or its submodule is built.

| Variable | Default | Meaning |
|----|----|----|
| `MSTAR_VIT_BATCHING` | `0` | BAGEL: batch several requests through the ViT encoder in one forward. Off because packed images give small bf16 drift, which can flip a greedy (`temperature=0`) token downstream. |
| `MSTAR_VIT_ACCELERATOR_GRAPH` | `0` | BAGEL: capture the ViT block loop as accelerator graphs, which removes per-layer launch overhead on small images at the cost of one graph per batch size and token bucket. Needs `model_kwargs.accelerator_graph` (BAGEL's default is true). The config's `prefill_token_buckets: {vit_encoder: {vit_block_loop: [...]}}` sets the buckets. |
| `MSTAR_VIT_ACCELERATOR_GRAPH_BATCH_SIZES` | `1,2,4` | Comma-separated batch sizes to capture; empty captures none. Read only with `MSTAR_VIT_BATCHING=1`; otherwise only batch size 1 is captured. |
| `COSMOS3_DISABLE_ACCELERATOR_GRAPH` | unset | Cosmos3: any nonempty value turns off the denoise, prefill and reasoner captures. `model_kwargs.accelerator_graph: false` turns them all off too, and this variable cannot turn them back on. |
| `COSMOS3_DISABLE_PREFILL_ACCELERATOR_GRAPH` | unset | Cosmos3: any nonempty value turns off only the prompt prefill captures (the DiT's, and the reasoner's text, mixed and vision prefills). Denoise and reasoner decode captures stay on. |
| `COSMOS3_GEN_CAPTURE_RES` | `model_kwargs.gen_capture_image`, else `192x320,480x832,720x1280` | Cosmos3: image denoise resolutions to capture, as comma-separated `HxW`. A tier above `COSMOS3_GRAPH_MAX_LATENT_AREA` is still skipped. |
| `COSMOS3_GEN_CAPTURE_BS` | `1` | Cosmos3: denoise batch sizes captured per resolution (for example `1,4,8`), so concurrent requests replay a padded graph instead of running eagerly. |
| `COSMOS3_GEN_CAPTURE_VIDEO` | `model_kwargs.gen_capture_video`, else none | Cosmos3: video denoise tiers to capture, as comma-separated `HxWxF` (for example `480x832x29`). |
| `COSMOS3_GRAPH_MAX_LATENT_AREA` | `model_kwargs.graph_max_latent_area` (`2000`) | Cosmos3: capture only tiers whose latent height x width is at most this; larger tiers run eagerly, where a graph is slower. |
| `COSMOS3_PREFILL_CAPTURE_BS` | `1` | Cosmos3: batch sizes of the prompt prefill captures. The config's `prefill_token_buckets` sets their token buckets. |
| `COSMOS3_COMPILE_VAE` | `1` | Cosmos3: `0`, `false`, `no` or `off` stops torch.compile of the VAE decode, which otherwise traces once per new output shape. |
| `COSMOS3_PNG_COMPRESS` | `0` | Cosmos3: zlib level of PNG image outputs. PNG is lossless at every level; a higher level trades encode time for size. |
| `COSMOS3_X264_PRESET` | `ultrafast` | Cosmos3: libx264 preset for MP4 video outputs, encoded at CRF 18. |
| `MSTAR_FLEX_BACKEND` | unset | Waypoint's ring-cache attention. Unset uses `FLASH` (flash-attn-4) when it imports and torch is 2.11 or newer, else `TRITON` with a warning. `TRITON` always picks the Triton kernel; `FLASH` fails at startup instead of falling back. |
| `MSTAR_KOKORO_STEP_LOG` | unset | Kokoro: any nonempty value logs one line per batched step (batch size, text bucket, frame groups, ms). It syncs the device, so it slows serving. |
| `MSTAR_OMNIVOICE_MODEL_PATH` | unset | OmniVoice: load weights from this local directory instead of the checkpoint the registry names, for example a fine-tune of the same architecture on a mounted volume. |
| `WAN22_VAE_DECODE_TILING` | the Wan2.2 config's `vae_decode_tiling`, `auto` | Wan2.2 VAE decode path. `auto` decodes untiled when free GPU memory is at least 1.3 times the estimated untiled peak for the output size, and tiled otherwise; `tiled` and `untiled` force one. The chosen path is logged per request. |

## Serving (API server) {#serving-api-server}

Read in the API server process that `mstar-serve` starts, whichever frontend serves HTTP.

| Variable | Default | Meaning |
|----|----|----|
| `MSTAR_API_KEY` | unset | API key; `--api-key` overrides it. When set, every route except `/health` and `/metrics` needs `Authorization: Bearer <key>`, WebSocket handshakes included; empty turns the check off. Both frontends apply it: the launcher passes it to `mstar-server`, not to the conductor or workers. `MStarClient` sends it when not given `api_key`. See [API key](/serving#api-key). |
| `MSTAR_MAX_BODY_MB` | `128` | Request body limit on every route of both frontends; a larger body gets a 413. `/v1/audio/transcriptions` keeps its own 512 MiB file cap when this is lower. It also caps one WebSocket message unless the config sets `ws_max_message_mb` (a larger message closes the socket with 1009). A client that writes the whole body before reading the reply can see a connection reset instead of the 413; `Expect: 100-continue` gets the 413 first. |
| `MSTAR_LOG_REQUESTS` | unset | `1` logs each request's lifecycle (submitted, queued at capacity, admitted, done, torn down) at any `--log-level`, on either frontend, as DEBUG lines on the `mstar.requests` logger. Without it the conductor logs a summary once a minute. |
| `MSTAR_ROOT_PATH` | `""` | Serve under a URL prefix, for an ingress that routes the deployment at a prefix without stripping it (Run:AI serves a workload at `/<project>/<job-name>/`); without it every route answers 404 there. Prefixed and bare paths both reach a route, on both frontends. |
| `MSTAR_MAX_IMAGES_PER_REQUEST` | `10` | Largest `n` one `/v1/images/generations` request may ask for; `n` outside 1 to this value is a 400 before anything is submitted. Both frontends and the Dynamo bridge read it. |
| `MSTAR_TOKENIZE_PARALLEL` | `1` | Before a long prompt is encoded as parallel chunks, set `TOKENIZERS_PARALLELISM=true` for the process: the Rust tokenizer uses its thread pool only while that reads true, and serving environments often export it false. `0` leaves the variable alone. |
| `MSTAR_TOKENIZE_CHUNK_CHARS` | `4096` | Prompts longer than this many characters are cut into chunks and encoded as one parallel batch, with the same ids as one encode. Used by the prompt processing of Qwen3.5, Muse Glimmer, Phi-4-multimodal and Ripple. `0` turns chunking off. |
| `MSTAR_TOKENIZE_MAX_CHUNKS` | `8` | Most chunks one prompt is cut into. |
| `MSTAR_SILERO_VAD_PATH` | unset | Silero VAD ONNX file (`silero_vad.onnx`) for `/v1/realtime` `server_vad` turn detection. Unset, the copy in the `silero-vad` package (`mstar-ai[vad]`) is used; with neither, or with a file whose inputs or outputs differ, `server_vad` sessions are refused. Never downloaded. |
| `MSTAR_SMART_TURN_PATH` | unset | Pipecat Smart Turn v3 ONNX file for `/v1/realtime` `semantic_vad`. Unset, `smart-turn-v3.2-cpu.onnx` from `pipecat-ai/smart-turn-v3` in the local Hugging Face cache is used if present; otherwise `semantic_vad` sessions are refused. Never downloaded. |

## Serving (Rust frontend) {#serving-rust-frontend}

Read by `mstar-server`, the default HTTP frontend (see [Installation](/installation#rust)).

| Variable | Default | Meaning |
|----|----|----|
| `MSTAR_SERVER_BIN` | unset | Path to the `mstar-server` binary. Lookup order: `--rust-frontend-bin`, this variable, the environment's scripts directory (where the Linux wheels install it), `$PATH`, then `rust/server/target/release`. In a checkout, a binary built from other sources is skipped, or used with a warning when the flag or this variable names it. |
| `MSTAR_SERVER_HOST` | `127.0.0.1` | Address `mstar-server` binds. The launcher sets it from `--host` (default `0.0.0.0`) only when it is unset, so an exported value overrides `--host`. |
| `MSTAR_REQUEST_TIMEOUT_S` | `600` | Per-request budget in seconds; on expiry the client gets an error and the request is aborted in the backend. `mstar serve` sets it from `--timeout`. `0` times every request out; a negative, non-finite or unreadable value means the default. |
| `MSTAR_MAX_CONCURRENT_REQUESTS` | `512` | In-flight generation requests the frontend admits; beyond it clients get an immediate 503 instead of queueing into the request timeout. `/health`, `/metrics` and `/v1/models` bypass the cap. |
| `MSTAR_ALLOW_REMOTE` | `0` | `1` lets requests name `http(s)` media URLs, fetched server-side by both frontends (at most 3 redirects and 30 s, no proxy). A host that resolves to a loopback, private, link-local, multicast or reserved address, cloud metadata included, is refused unless allowlisted. Failures are a 400. `mstar-server` trusts the bundled Mozilla roots, not the system store, so a private CA works only with `--python-frontend`. |
| `MSTAR_REMOTE_ALLOWED_HOSTS` | unset | Comma-separated hosts and `*.suffix` patterns (`*.example.com` matches its subdomains, not `example.com`). When set, only these hosts are fetched, on every redirect, and they skip the address check. An entry matches only the canonical spelling of a host, so `127.1` or `0x7f000001` never match. |
| `MSTAR_REMOTE_MAX_BYTES` | `67108864` (64 MiB) | Largest remote media file fetched, checked against `Content-Length` and while streaming. |
| `MSTAR_TOKENIZER` | unset | Path to a `tokenizer.json` for frontend tokenization. Leave it unset: the API server's bridge to `mstar-server` refuses to start while it is set, since the model side owns tokenization. |

## Request media {#request-media}

Read by the model's media loaders in the data worker, behind either frontend. The data worker checks all four at startup, so an invalid value stops the server. The pixel and audio caps hold for a request's files together.

| Variable | Default | Meaning |
|----|----|----|
| `MSTAR_MAX_IMAGE_PIXELS` | `89478485` | Pixels a request's images may decode to, checked from each header before decoding; over it, a 400. PNG, JPEG, WebP and GIF are read (FLUX.2 klein also reads BMP and TIFF); other formats get a 400. A GIF or animated WebP is read as its first frame, turned upright by its EXIF orientation. |
| `MSTAR_MAX_VIDEO_PIXELS` | `1073741824` | Pixels a request's videos may decode to, summed over the frames the model decodes, each frame counting as at least 64x64; over it, a 400. At 1080p30 the default allows about 17 s of video on Cosmos3, which decodes every frame, and about 259 s on Qwen3-Omni and Qwen3.5, which decode 2 frames a second. |
| `MSTAR_MAX_MEDIA_FILES` | `16` | Images, audio clips and videos one request may attach together; more get a 400 before any is decoded. Some models take fewer: Qwen3-TTS, Chatterbox, Whisper and Higgs Audio take one audio clip. |
| `MSTAR_MAX_AUDIO_SECONDS` | `3600` | Seconds a request's audio may decode to, checked from each header and again while decoding; over it, a 400. |

## Worker scheduling {#worker-scheduling}

| Variable | Default | Meaning |
|----|----|----|
| `MSTAR_TP_ASYNC_SCHED` | config's `tp_async_sched`, else `1` | Async scheduling for lockstep-parallel (TP, SP, CFG) nodes. `1`: the instance leader speculates step N+1 during forward N and broadcasts it, so every rank submits N+1 as soon as N completes. A comma-separated list of node names (`thinker,talker`) turns it on for those nodes only. `0`: the leader schedules after N. Set it the same on every rank; workers refuse to start on a mismatch. Keep `MSTAR_ENGINE_STEP_SYNC` at `0` with it. |
| `MSTAR_ENGINE_STEP_SYNC` | `0` | `1` blocks the GPU thread on each step's outputs before it returns, so launches run one step ahead instead of two and step N+1's GPU work no longer overlaps step N's postprocess. Use it only where two steps overflow the CUDA launch queue and block a launch. |
| `MSTAR_PRE_PLAN_SPEC` | config's `knobs: pre_plan`, else `1` | Pre-plan the speculative batch's attention on a dedicated thread while the previous replay runs. `0` plans inline on the GPU thread, which Whisper Turbo's config sets: its steps are too short to hide the planning in. |
| `MSTAR_NUM_SLOTS` | `2` | Buffer slots a node rotates through when it double-buffers (pre-planning on, or a resource that stages into a reused host buffer), so step N+1 plans into buffers replay N is not reading. Values below 2 become 2 with a warning. A node that neither pre-plans nor has such a resource uses one slot. |
| `MSTAR_STEP_THREADS` | config's `knobs: step_threads`, else `threaded` | Where a worker runs a step's host work. `threaded` runs admit, plan and the launch on its GPU thread and the pre-plan on its plan thread. `serial` runs them on the main thread, so host work overlaps the GPU but not other host work. |
| `MSTAR_STEP_THREAD_CORE` | config's `knobs: step_thread_core`, else `auto` | Pins each worker's main, GPU and plan threads, and the API server's message thread and bridge, on CPUs of their own, so handoffs do not wait for a core to wake from deep idle. `off` pins nothing. `always`: three cores per worker, one for the API server. `siblings`: a worker's threads on one core's hardware threads. `auto` pins nothing and logs why. A number names the first worker's core. Servers sharing `/tmp` take different cores. No effect on macOS. |
| `MSTAR_IDLE_HOLD` | config's `knobs: idle_hold`, else `off` | `qos` has the API server write a 10 µs latency to `/dev/cpu_dma_latency` and hold it for its life, keeping every CPU of the host out of slower idle states (C1 and C1E stay allowed). The hold is host-wide and spends power while idle. Containers usually hide the device; startup then carries on and the log says so. |
| `MSTAR_DECODE_BUCKETS` | `1,2,4,8,16,32,48,64,96,128` | Decode batch sizes a `SampledTokenDecoder` LLM node captures; a step runs at the smallest bucket that holds its rows. Narrow it (`1,2,4,8,16,32`) to save graph memory. It reaches Qwen3.5, Muse Glimmer and the Cosmos3 reasoner (whose own default is `1,2,4,8,16,24,32,48,64`); `MSTAR_QWEN35_DECODE_BUCKETS` overrides it for Qwen3.5 alone. Canary, Canary-Qwen, Qwen3-ASR, Orpheus, Higgs Audio and Command A+ pin their own. |
| `MSTAR_LAZY_PUBLISH` | `1` | Publish resource state (KV pages, positions) only for the requests whose frame or completion carries it. `0` builds it for every request on every step. |
| `MSTAR_MAX_CONSECUTIVE_SPEC_STEPS` | `1024` | Cap on back-to-back speculative steps before the leader yields to other ready work. `0` turns speculation off. A non-integer value is ignored with a warning. |
| `MSTAR_SPEC_PEEK_FOR_FAIRNESS` | `1` | Yield the speculation chain only when another (node, walk) is ready right now; `0` uses the consecutive-step cap alone. |
| `MSTAR_LAUNCH_WAIT_MS` | `5` | Milliseconds the speculative submitter waits off the GIL for the GPU thread to reach the launch. An unreadable, `nan` or `inf` value is ignored with a warning; a negative one becomes `0`. |
| `MSTAR_KV_CHAIN_LAZY_STEPS` | config's `knobs: kv_chain_lazy_steps`, else `1` | Decode steps of sampled ids the KV manager holds back before it extends the requests' prefix-cache keys, so it extends once per batch of steps. A page key then appears up to that many steps late, and a request that finishes in between may leave its last page unindexed. |
| `MSTAR_WORKSPACE_BUFFER_MB` | `512` | Starting size of each FlashInfer attention workspace, per plan label and slot. A startup plan that asks for more grows it. Raise it when an eager step fails asking for more, since a captured graph holds the workspace's address. A ragged resource that declares `workspace_mb` (LTX-2.5) starts there and ignores this. |
| `MSTAR_KV_PINNED_INDPTRS` | config's `knobs: kv_pinned_indptrs`, else `0` | The KV plan writes FlashInfer's index arrays into page-locked host buffers, so the copies FlashInfer's `plan` issues are asynchronous. Costs one CUDA event per plan. |
| `MSTAR_GC_GEN0_THRESHOLD` | config's `knobs: gc_gen0_threshold`, else `0` | Generation-0 garbage-collection threshold a worker sets after warmup; `0` keeps CPython's 700. At high batch, 700 runs a collection almost every decode step and a full one every few hundred; a large value such as `50000` stops that, at the cost of holding that many young objects. |
| `MSTAR_RESIDENT_PLANNING` | config's `knobs: resident_planning`, else `auto` | `auto` runs a node's captured decode steps off per-request tables on the device where the model and every resource of the node support it; the worker log says why a node stays on the host. `off` plans every step on the host. The tables are sized at startup from the largest capture batch and the KV pool's `max_seq_len`. |
| `MSTAR_DEVICE_LOOPBACK` | config's `knobs: device_loopback`, else `1` | Lets a decode node keep its loop-back token on the device: the sampler writes each request's last token where the next step reads it, so no per-request tensor is routed. Applies to the decode walks of Qwen3.5, Muse Glimmer, Higgs Audio, Qwen3-ASR, the Cosmos3 reasoner, Qwen3-Omni's text-only Thinker and Whisper, when the sampler has graph buffers. `0` uses the per-request tensor path everywhere. |
| `MSTAR_INGRAPH_DECODE_ROPE` | config's `knobs: ingraph_decode_rope`, else `0` | A captured Qwen3.5 text prefill or mixed step builds its rotary tables inside the graph instead of before the replay; a captured decode step always does. An experiment knob. |
| `MSTAR_SAMPLER_INGRAPH_SCATTER` | config's `knobs: sampler_ingraph_scatter`, else `1` | The captured sampler reads its RNG offsets and writes the advanced offsets and sampled tokens inside the graph, so a replayed decode step issues no launches for them afterwards. Its buffers hold `MSTAR_SAMPLER_SLOTS` requests, and further requests wait to be admitted. Applies on one rank, to nodes that read tokens back on the device (Qwen3.5, Qwen3-ASR, Whisper, the Cosmos3 reasoner); above one rank the scatter runs after the replay, as with `0`. |
| `MSTAR_SAMPLER_SLOTS` | config's `knobs: sampler_slots`, else `4096` | Requests the captured sampler's buffers hold when `MSTAR_SAMPLER_INGRAPH_SCATTER` is on (at least the node's largest capture batch): the most requests admitted at once on such a node. |
| `MSTAR_PY_SWITCH_INTERVAL_SEC` | unset (Python's default) | A worker calls `sys.setswitchinterval` with this many seconds before its main loop starts. A value that is not a number is ignored with a warning. |
| `MSTAR_DRAIN_TTL_S` | `120` | Seconds the conductor waits for every worker to release a finished, aborted or failed request before it frees the request anyway, so a crashed or hung worker cannot hold a `max_concurrent_requests` slot forever. |
| `MSTAR_RUST_SEND_TIMING` | unset | `1` makes the Rust runtime print, every 500 calls, how long the worker's per-step send spends in its own work against the whole call. A diagnostic. |
| `MSTAR_PHASE_TIMING` | `0` | `N > 0`: every N iterations, log p50, p95 and mean per phase of the worker main loop (speculate, await_gpu, submit_spec, ...). |

## Compilation {#compilation}

| Variable | Default | Meaning |
|----|----|----|
| `MSTAR_COMPILE_LEVEL` | `1` | How much a captured forward's compile tunes; `mstar serve -O` sets it. `0`: torch.compile's default. `1`: coordinate descent tuning. `2`: `max-autotune-no-cudagraphs`. A capture that names its own `compile_mode` keeps it. See [Compile levels](/cold-start#compile-levels). |
| `MSTAR_REQUIRE_ACCELERATOR_GRAPHS` | `0` | `1` makes a worker fail at startup when any accelerator graph bucket could not be captured. By default a failed capture is logged at ERROR with a per-runner summary and that bucket runs eagerly, much slower. A bucket a resource declines to capture counts as not captured too, such as a Qwen3.5 prefill bucket above `linear_attn.max_captured_prefill_tokens` on ROCm ([Kernels](/hardware#amd-kernels)). |
| `MIOPEN_DEBUG_CONV_IMPLICIT_GEMM_ASM_FWD_GTC_XDLOPS_NHWC` | `0` on ROCm | MIOpen's variable. On ROCm the conductor sets `0` unless you set it, which turns off MIOpen's split-K implicit-GEMM conv solver: it is not deterministic, so same-seed outputs would not repeat. Other platforms leave it unset. |
| `MIOPEN_DEBUG_CONV_IMPLICIT_GEMM_ASM_BWD_GTC_XDLOPS_NHWC` | `0` on ROCm | The same, for the backward-data solver that a `ConvTranspose1d` runs (vocoder upsamplers). |
| `MSTAR_RECOMPILE_LIMIT` | `84` | Dynamo's recompile limit, clamped to \[8, 256\]. Raise it if the logs show `hit config.recompile_limit`. |
| `MSTAR_KERNEL_TABLES` | unset | Directories of tuned kernel-config tables (`os.pathsep`-separated), searched before `mstar/kernels/tables`. `python -m benchmark.kernels.sweep ... --out DIR` writes one. Set it the same on every node, so every rank of a lockstep instance picks the same configs. |
| `MSTAR_COMPILE_DETERMINISTIC` | config's `knobs: compile_deterministic`, else `0` | `1`: Qwen3.5's decode capture compiles in Inductor's deterministic mode, as its prefill, mixed and vision captures always do, so greedy output repeats across server processes and the cold start is shorter, at some cost to one-row decode speed. Only Qwen3.5's text walks read it. |
| `TRITON_PTXAS_BLACKWELL_PATH` | torch's ptxas, when needed | Triton's variable: the ptxas it runs for sm_100 and newer. ptxas before 13.1.115 (Triton 3.7.1 bundles 13.1.80) miscompiles some integer floor divisions on sm_103. Unset, on a compute capability 10.x GPU where only torch's ptxas is new enough, the conductor points its workers at `torch/bin/ptxas` and sets `TORCH_COMPILE_CACHE_KEY_TAG`, so the compile cache does not reuse the old ptxas's kernels. A value you set is kept. |
| `TORCHINDUCTOR_CACHE_DIR` | `$XDG_CACHE_HOME/mstar/torchinductor` (`~/.cache/mstar/torchinductor`) | torch's variable. M\* sets this default when `mstar.engine` is imported, so compiled graphs and autotune picks survive restarts. An exported value wins, and a home that can't be written keeps torch's `/tmp/torchinductor_<user>`. Point it at an empty directory to measure a cold start. See [Compile cache](/cold-start#compile-cache). |
| `TRITON_CACHE_DIR` | `$TORCHINDUCTOR_CACHE_DIR/triton` | Triton's variable, defaulted once `TORCHINDUCTOR_CACHE_DIR` is resolved, unless that fell back to torch's default. An exported value wins. Holds every Triton kernel, Inductor's and others'. |

## Set by the launcher {#set-by-the-launcher}

`mstar-serve` sets these for the processes it starts. Leave them unset.

| Variable | Default | Meaning |
|----|----|----|
| `MSTAR_SHM_ARENA_PLAN` | set by the API server | `<segment MiB>x<max segments>` for every arena of the deployment (`0x0`: none, send by files), measured once so each arena gets the same size whatever order the processes start in. `MSTAR_SHM_ARENA_SEGMENT_MB` and `MSTAR_SHM_ARENA_MAX_SEGMENTS` take precedence. |
| `MSTAR_STEP_CORE_SET` | set by the API server | Which core set the API server locked under `step_thread_core`, for the conductor and workers it starts. |
| `MSTAR_OPENAI_ADAPTER` | set by the launcher | The class name of the model's adapter in `ADAPTER_REGISTRY`, which picks the OpenAI translation `mstar-server` uses. A `mstar-server` started without it answers 404 on `/v1/*`. |
| `MSTAR_SAMPLE_RATE` | `24000` | Sample rate stamped on `mstar-server`'s WAV output; the launcher sets it to the model's audio output rate. |
| `MSTAR_LIBSNDFILE` | set by the launcher | The libsndfile `mstar-server` opens to encode `mp3`, `flac` and `opus` speech, set to the library `soundfile` loaded. Without it only `wav` and `pcm` are produced. It is opened at run time, never linked. |
| `MSTAR_SERVED_MODELS` | unset | The names a request's `model` may carry, as JSON: the base model's names and the LoRA adapters served at launch. |
| `MSTAR_TRANSCRIPTION` | unset | What `mstar-server`'s `/v1/audio/transcriptions` needs from the served model, as JSON. |
| `MSTAR_OPENPI` | unset | The deployment's openpi policy, as JSON; unset serves no socket at `/`. |
| `MSTAR_WS_MAX_BYTES` | the body limit | The largest WebSocket message `mstar-server` reads, in bytes: the config's `ws_max_message_mb`. |
| `MSTAR_CLIENT_STREAMS` | `[]` | The model's client streams, as JSON: on `/generate/ws` a request to a model with any is a live call. |
| `MSTAR_REALTIME` | unset | What `mstar-server`'s `/v1/realtime` runs with, as JSON. |

## Tests and debugging {#tests-and-debugging}

| Variable | Default | Meaning |
|----|----|----|
| `MSTAR_KV_DEBUG_ASSERTS` | `0` | `1` checks the KV page bookkeeping after every admit, commit and page change: pages against the streams holding them, reservations against free and evictable pages, each commit against its request's layout, and recurrent snapshot keys against the KV chain. Above one rank a follower stops if its reservations differ from rank 0's. For tests and debugging only. |
| `MSTAR_ASR_DATA` | `data/asr` | `test/asr` GPU parity tests: the set `benchmark.asr_data` built. |
| `MSTAR_WHISPER_REPO` | `openai/whisper-large-v3-turbo` | `test/asr/test_whisper_parity.py`: the Whisper checkpoint to compare. |
| `MSTAR_QWEN_ASR_REPO` | `Qwen/Qwen3-ASR-1.7B` | `test/asr/test_qwen3_asr_parity.py`: the Qwen3-ASR checkpoint to compare. |
| `MSTAR_QWEN_ASR_REF` | `refs/Qwen3-ASR` | `test/asr/test_qwen3_asr_parity.py`: a checkout of the qwen-asr SDK, which the reference transcripts come from. |
| `MSTAR_QWEN_ASR_REF_SITE` | unset | `test/asr/test_qwen3_asr_parity.py`: a directory holding transformers 4.57, put first on the path of the subprocess that runs the SDK. Unset under transformers 5, the SDK comparison is skipped. |

`MSTAR_SIM` and the `MSTAR_SIM_*` variables belong to `python -m mstar_sim`, a Linux-only simulator in the checkout that runs M\* on emulated GPUs for correctness tests. Its flags set them; `mstar_sim/README.md` describes the rest.
